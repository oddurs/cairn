## Install

<Callout>
These pages describe the **1.0.0-alpha.1 development line**, including format-4
UUID identities. Prebuilt releases and Homebrew still install stable 0.3.0
(format 3). Build from source for the development version, and upgrade Harrow to
its matching 0.2.0-alpha.1 line before migrating an existing project.
</Callout>

A prebuilt binary, with no Rust toolchain needed:

```sh
curl -fsSL https://raw.githubusercontent.com/oddurs/cairn/main/install.sh | sh
```

It detects your platform, verifies the release checksum and installs to
`~/.local/bin`. Homebrew takes three commands, because recent versions require
third-party taps to be trusted explicitly:

```sh
brew tap oddurs/cairn
brew trust oddurs/cairn
brew install cairn
```

From source, `cargo install --git https://github.com/oddurs/cairn cairn-md`.

<Callout>
The package is called `cairn-md` because `cairn` belongs to an unrelated crate.
The binary it installs is `cairn`.
</Callout>

## Create a project

```sh
$ cairn init
created cairn.toml
created cairn/items/
```

That writes the schema and the directory items live in. Run it at the root of a
repository — items are meant to be committed alongside the code they describe.

`cairn init --preset minimal --bare` starts from a small schema without example
items. The default writes a fully commented schema to adapt to your project.

## The loop

Four commands carry the day-to-day. Everything else is machinery underneath
them.

<Terminal name="next" caption="Work that is genuinely startable. Anything waiting on unfinished work is excluded, and what is already under way comes first — the most useful next action is usually finishing something." />

<Terminal name="claim" caption="Takes the top-ranked unclaimed item, writes your name into it, and prints its body so work can begin. It refuses an item somebody else holds, and one that is blocked." />

Then record what you learned and finish:

```sh
$ cairn note 00000003 "Chose the authorization code flow; implicit is deprecated."
$ cairn close 00000003
```

Use the reference printed by your claim; `00000003` is the UUID prefix in the
recorded example, not a number allocated to new work. JSON and stored references
use the full immutable UUID. Old numbers remain aliases in migrated projects.

`cairn note` appends to the item under a dated heading. A status records what
was decided; a note records why, which is the difference between a backlog and a
list of things nobody remembers rejecting.

`next` excludes unfinished dependencies; it does not decide which ideas your
project has approved. If your schema uses `planned` for selected work, scope an
agent's claim with `cairn claim --next --filter 'status=planned'`.

[Harrow](https://github.com/oddurs/harrow) is the optional terminal counterpart.
Run it beside an editor or agent to watch the same backlog and make interactive
decisions. It reads the files directly and delegates changes to Cairn.

## What gets written down

An item is a Markdown file, and that is the whole storage format.

<Terminal name="item" />

Everything above the closing `---` is checked against the schema. The body is
yours; conventions such as acceptance checkboxes and proposals let tools help
you work it. Edit the file in your editor or from the command line — both keep
working, and changing a title normally renames the file to match.

## The generated roadmap

`ROADMAP.md` is built from the items, and rebuilt whenever one changes. Never
edit it by hand.

```sh
$ cairn render
wrote ROADMAP.md  14 items
```

<Terminal name="check" caption="cairn check --render --strict belongs in continuous integration. It validates every item against the schema and proves the committed roadmap still matches them, which is what stops a roadmap from quietly becoming fiction." />
